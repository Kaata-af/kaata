## New store images

All **36** refreshed opaque RGB PNGs passed dimensions, fonts, text clipping,
image loading and visual checks. Six panels cover Home and multiple currencies,
customer notes and tallies, the calculator, inline search, optional app lock
and reminders. They retain the Persian white/blue campaign and yellow–blue–red
footer. These are source-faithful promotional compositions with fictional data,
not native device captures.

Play received six phone, six 7-inch and six 10-inch tablet images. Apple received
six medium iPhone, six legacy large iPhone and six iPad images. All 18 Apple
images were **COMPLETE**, with exact checksums, dimensions and order, before
review submission. App lock replaced the old onboarding panel. The existing
icon, Play feature graphic, listing text and other locales were preserved;
What's New was updated with the committed production notes.

Sizes, source references and ordered hashes are in the
[asset guide](store-assets/README.md),
[Play manifest](store-assets/play-screenshots-manifest.json) and
[Apple manifest](store-assets/apple-screenshots-manifest.json).

## Readiness and delivery

- All 29 focused mobile suites passed on the unchanged tested app runtime.
  The original artifacts passed 86 AAB, 14 local APK, 10 Google-signed APK and
  59 IPA checks, including original signers, native passcode support and Android
  16 KiB alignment. The release APK also passed its offline cold-start check.
- A fresh isolated PostgreSQL 18 run passed **1,155 backend tests/subtests**,
  with no failures or skipped database tests. Only the optional bill-preview
  writer was skipped. The loopback cluster on port 55484 was stopped afterward.
- The existing review account signed in, read all eight required live server
  capability flags and signed out. No ledger or settings data was read or
  changed, and no messages were sent. Apple review credentials were compared
  privately with the current credential file; private values were never logged.
- Play acknowledged one guarded commit, `14140690885588962384`, combining the
  18 images with promotion of the existing verified build 82. Independent
  readback verified screenshot hashes/order, exact build, listing text, icon,
  feature graphic and non-production tracks. A later read confirmed production
  82 was published. No bundle was uploaded again and no review was cancelled.
- Apple attached tested build 48 to version
  `69e4c650-0ab1-4617-98c8-62be7b5d3c6c`. Slow processing required sealed,
  journalled continuations and capacity-limited batches. A task-owned read-only
  polling process was stopped at a fully acknowledged checkpoint; accepted
  uploads were never replayed. Missing list metadata was checked through direct
  image details without substituting local values. All 73 staging operations
  were acknowledged before independent final readback.
- Apple review submission `6d11f868-62d3-46c4-a3da-5bdb52b7b925` used exactly
  three acknowledged review operations. Version and submission were both
  `WAITING_FOR_REVIEW`, with `AFTER_APPROVAL` release configured. All 15
  historical versions were preserved; public iOS 2.2.4 remained unchanged.

## Retained limitations and evidence

The original strict Play post-commit inventory check remains failed: inactive
old bundle 59 disappeared from Google's returned inventory. Read-only
reconciliation confirmed no added or modified bundle, all remaining 30 entries
unchanged and the exact tested build 82 retained. The removed build was inactive
before and after; its disappearance is recorded without assuming a cause.
The original failure was not overwritten and no corrective store write was made.

Live capability support passed, but health still reports `dev`/`unknown`; an
exact running container SHA and old-worker drain were not independently
attested. No manual deployment or SSH host-key bypass was performed. App Store
approval and public iOS availability remain pending. Public CDN screenshot
propagation was not independently pixel-checked.
