## October 27 export integrity audit

The follow-up audit found and fixed gaps in the new models:

- Customer CSV/PDF statements now include private pre-link history separately
  from the current opening balance. Earlier records retain dates, amounts and
  chapter markers without adding the same debt twice. Each multi-currency file
  captures one calendar, keeping its date columns aligned during preference changes.
- Complete-history bill links use version 3 with explicit capability and upload
  acknowledgement checks. Frozen history and clearance anchors are separate
  from current balances. Versions 1 and 2 remain supported. Currency sections
  have a bounded limit of 256; aggregate 5,000-entry, 5,000-marker and 4 MiB limits
  still prevent silently shortened bills. New routes retain the sharing image,
  crawler rules and token redaction, including the shared-snapshot API logs.
- File exports and bill preparation wait for incomplete shared history instead
  of presenting a missing cache as zero or a complete record. The ordinary
  customer page can still display its known current balance.
- Cloud snapshots retain the original signed enabled-currency setting events
  independently of the snapshot cursor. Restoration preserves explicit disabled
  currencies, event authority and newer local settings. Local SQLite backups
  remain complete without a schema-specific conversion.
- Expo Go PDF output now reads print bytes through the native print API and
  writes them within the experience's scoped cache. Installed builds retain
  the awaited file move. Expo Go detection uses its native module presence
  rather than the unreliable SDK 58 legacy execution-environment value.

Verification includes the real Android Expo Go CSV bytes and a generated
two-page PDF using synthetic AFN/USD records, alongside signed restore, money,
shared-account, date, all-currency, bill validation/rendering, privacy and type
checks. No real ledger records were modified, no share/save dialog was opened,
and no application build or deployment was performed. Backend and website fixes
are local and must be deployed together before the new bill/restore behavior
is available against that server. Native iOS export/save review remains a
release-candidate check.
