## Server rollout correction

The initial 098 migration rolled back automatically on the populated production
database. PostgreSQL restricts the search path during index construction, so an
unqualified helper inside the new PL/pgSQL function could not resolve. The earlier
fresh-database tests created an empty index and missed this invocation.

098 now qualifies the helper with `public`; 099 also pins the function search path
for installations that had applied the original migration on an empty database.
New regression coverage upgrades populated accounts, rebuilds the index, repairs
the original installed body and checks restricted-path matching. These tests and
the search/privacy cases passed on isolated PostgreSQL 18.

At 16:51 UTC production had both migrations applied, a valid search index and a
healthy new runtime containing the search code. Public health and search returned
success. The health endpoint still reports an unknown commit; deployment source,
schema and runtime marker evidence are recorded separately.
