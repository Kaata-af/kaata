## Build and delivery boundaries

Android is built locally from the committed candidate using a fresh SDK 58
native project, the production environment and original upload signer. The
guarded internal-only uploader validates the code and bundle hash and preserves
production, closed tracks and store listings. No production promotion runs.

iOS uses `.github/workflows/ios-production-local.yml` on the public repository's
standard Mac runner, with an exact source-commit guard and frozen signing
credentials. It retains the IPA and identity receipt without uploading. The
downloaded artifact is independently verified before its TestFlight-only upload
and existing-group readiness checks. App Store versions and reviews are read-only.

Pushing `main` triggers the existing Dokploy backend/web deployment. Matching
support enables version-3 full-history bills, their preview/privacy routes and
signed enabled-currency/bill-link preference history in cloud snapshots. There
are no new backend migration files in the pending range from remote `cae5320`.

At this source checkpoint builds, deployments and testing uploads still require
completion and verification. Build identifiers and delivery receipts will be
recorded after those operations; this document does not claim phone QA or
tester availability merely from a queued job.

## Android 74 cold-launch failure and corrective candidate 75

The follow-up Google-signed APK check updated the Xiaomi in place, preserving
its UID and app data. The first cold launch then failed in AndroidX Startup's
WorkManager initializer, before JavaScript or the ledger opened. Build 74 must
not be treated as a healthy testing release. Production 73 and iOS 42 remain
unchanged; the user's unsent SMS draft was untouched.

The captured exception was `Failed to create an instance of class
androidx.work.impl.WorkDatabase.canonicalName`. The resolved older Room 2.5.0
uses reflective construction. Actual DEX and R8 removal reports proved that
`WorkDatabase_Impl` had lost its public no-argument constructor. The two
WorkManager input-merger constructors were removed as well. These failures are
independent of the separately verified unused-resource pruning above.

[AGP 9's strict keep-rule behavior](https://developer.android.com/build/releases/agp-9-0-0-release-notes#behavior_changes)
requires explicit constructor retention for such older consumer rules. The
committed Expo build-properties configuration adds scoped public no-argument
constructor rules for Room database and WorkManager input-merger subclasses.
R8, obfuscation and resource shrinking remain enabled. Existing worker,
AndroidX Startup, Firebase and Expo reflection entry points were independently
audited; their explicit constructor rules and packaged constructors are present.

Android code 75 is the forward-only replacement. Its release gates must check
the actual DEX constructors and a cold launch of an exact release APK on a fresh
disposable emulator before any store upload. The Xiaomi's Google-signed package
cannot accept the locally upload-key-signed APK, so no signature workaround,
uninstall, downgrade or app-data clear is used. iOS 42 needs no rebuild for this
Android-only native configuration correction.
