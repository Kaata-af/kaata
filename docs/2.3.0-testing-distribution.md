# Kaata 2.3.0 testing distribution

Authorized October 27, 2026: push `main`, deploy matching backend and website
updates, build Android locally and iOS through the existing GitHub Actions Mac
workflow, then distribute through Play internal testing and the existing
TestFlight internal group. No public mobile release or App Store review
submission is authorized by this testing request.

## Candidate and verification

- App version **2.3.0**, Android code **74**, iOS build **42**. Read-only store
  checks found these identifiers unused; upload tools recheck the exact target.
- Application/package identity stays `af.kaata.app`; existing signing credentials
  are reused. Expo cloud build capacity is exhausted, so neither platform uses
  an Expo cloud build.
- Mobile verification covered all 109 selftest scripts across the initial batch
  and focused reruns. Five failed fixtures/environment checks were resolved:
  email auth, invitation acceptance, backup/restore, customer search and
  onboarding calendar. Session-deletion fixture warnings were also fixed.
  TypeScript and the updated Home/customer carousel regressions pass.
- The full shipped backend package trees (`./cmd/... ./internal/...`) passed
  **892 test/subtest cases**, with zero failures or database-test skips, using
  a disposable PostgreSQL instance. Only the optional preview-file generator was
  skipped. Ignored recovery scratch packages were excluded. The test cluster
  was stopped and removed; the development database was untouched.
- Web TypeScript, all **170 tests** and the local production compilation passed.
  The 46 guarded Play/TestFlight helper tests also pass.

## Build and delivery boundaries

Android is built locally from the committed candidate using a fresh SDK 58
native project, the production environment and original upload signer. The
guarded internal-only uploader validates the code and bundle hash and preserves
production, closed tracks and store listings. No production promotion runs.

iOS uses `.github/workflows/ios-production-local.yml` on the public repository's
standard Mac runner, with an exact source-commit guard and frozen signing
credentials. It retains the IPA and identity receipt without uploading. The
downloaded artifact is independently verified before its TestFlight-only upload
and existing-group readiness checks. App Store versions and reviews are read-only.

Pushing `main` triggers the existing Dokploy backend/web deployment. Matching
support enables version-3 full-history bills, their preview/privacy routes and
signed enabled-currency/bill-link preference history in cloud snapshots. There
are no new backend migration files in the pending range from remote `cae5320`.

At this source checkpoint builds, deployments and testing uploads still require
completion and verification. Build identifiers and delivery receipts will be
recorded after those operations; this document does not claim phone QA or
tester availability merely from a queued job.
