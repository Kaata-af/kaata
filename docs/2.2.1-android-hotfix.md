# Kaata 2.2.1 Android hotfix

Requested October 17, 2026: build locally, commit and push, and submit Android
2.2.1/versionCode 60 to Google Play production with the existing upload key.

## Fix and verification

Android 2.2.0/code 59 crashed when a customer was opened from search. The Mi 10T
trace reports `addViewAt` followed by "The specified child already has a parent."
The release mapping identifies the retained parent as `ScreenContentWrapper`.
The search route's layout-only wrapper became a native view when dismissal
changed `pointerEvents` to `none`, reparenting content during the native exit.
Keeping the wrapper non-collapsible preserves its native parent throughout.

The route regression fails for the old collapsible wrapper and passes with the
fix. Mobile TypeScript, search-sheet/search-focus, person-find, person-detail,
home-selection, search-controls and notification-navigation checks passed.
An isolated, signed release APK opened a queried search result with the keyboard
visible on the connected Xiaomi Mi 10T (Android 12), reached customer detail,
hid the keyboard and retained the same running process. The user independently
confirmed that customer taps work without crashes.

The production bundle uses `af.kaata.app`, version 2.2.1/code 60 and the production
backend. The offline `af.kaata.searchfix` APK is a separate device-test artifact.
The captured crash is in Android's native view mounting path; the iPhone did not
reproduce it. No iOS binary or submission is needed for this hotfix.

## Local build cache

React Native's Gradle JavaScript bundle task tracks source files but does not
track changes to `EXPO_PUBLIC_*` environment variables or `app.json`. After an
offline test build, a plain production `bundleRelease` reused that test bundle.
The first prepared Play edit was discarded before commit. No production release
was committed from it.

The production assets were regenerated explicitly with
`:app:createBundleReleaseJsAndAssets --rerun-tasks`, the production environment
from `eas.json`, and `EXPO_NO_DOTENV=1`, followed by `:app:bundleRelease`. Verify
the JavaScript inside the final signed AAB against the freshly generated bundle,
including the production backend and absence of the offline test backend. Native
manifest/version checks alone do not detect a stale JavaScript bundle.
